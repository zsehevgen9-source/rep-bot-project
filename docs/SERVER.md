# Маячок на сервере: бот работает, когда компьютер выключен

Бот переезжает с домашнего компьютера на **виртуальный сервер** — компьютер в дата-центре, который работает круглосуточно.
Входящие подключения боту не нужны (он сам забирает сообщения у MAX), поэтому **домен и сертификат не нужны**.
Нужен сервер с Ubuntu, 2 ГБ памяти и 20 ГБ диска.

Ниже — на примере **Yandex Cloud** (аккаунт и оплата там уже есть: YandexGPT и озвучка работают через него).
Подойдёт и любой другой российский VPS с Ubuntu 22.04/24.04 — тогда пропустите шаг 2 и возьмите у хостинга IP-адрес, логин и пароль/ключ.

> Данные детей остаются в России (серверы Yandex Cloud) — это важно для закона о персональных данных (152-ФЗ).

---

## Шаг 1. Ключ для входа на сервер (на своём компьютере, один раз)

1. Откройте **PowerShell** (Пуск → напишите «PowerShell»).
2. Вставьте команду и нажмите Enter:
   ```
   ssh-keygen -t ed25519
   ```
   На все вопросы просто жмите **Enter** (три раза).
3. Покажите открытую часть ключа:
   ```
   type $HOME\.ssh\id_ed25519.pub
   ```
   Появится строка вида `ssh-ed25519 AAAA… имя@компьютер` — скопируйте её **целиком**, она понадобится на шаге 2.
   Это открытый ключ, его можно вставлять на сайты. Файл `id_ed25519` без `.pub` — секретный, его никому не отправляйте.

## Шаг 2. Создать сервер в Yandex Cloud

1. Откройте [console.yandex.cloud](https://console.yandex.cloud) → ваш каталог → **Compute Cloud** → **Создать ВМ** (виртуальную машину).
2. Заполните (названия полей могут чуть отличаться):
   - **Образ**: Ubuntu **24.04 LTS**;
   - **Зона доступности**: любая, например `ru-central1-a`;
   - **Диск**: 20 ГБ (HDD подойдёт — дешевле);
   - **Вычислительные ресурсы** → своя конфигурация: платформа Intel Ice Lake, **vCPU: 2**, **гарантированная доля vCPU: 20%**, **RAM: 2 ГБ**;
   - **Прерываемая** — **выключить** (иначе Яндекс выключает сервер раз в сутки);
   - **Публичный IP-адрес**: Автоматически;
   - **Доступ**: по SSH-ключу. **Логин**: `mayak`. **SSH-ключ**: вставьте строку из шага 1;
   - **Имя ВМ**: `mayachok`.
3. Нажмите **Создать ВМ**. Через 1–2 минуты статус станет «Running».
4. Скопируйте **публичный IPv4-адрес** сервера (например, `51.250.12.34`) — дальше он везде вместо `IP`.

**Сколько стоит:** примерно 1 300–1 600 ₽ в месяц (2 vCPU с долей 20% и 2 ГБ памяти — около 1 220 ₽ за 30 дней, плюс диск и публичный адрес).
Точную сумму покажет калькулятор справа при создании ВМ. Деньги списываются с того же баланса, что и за YandexGPT.

## Шаг 3. Подготовить сервер

1. В PowerShell зайдите на сервер (вместо `IP` — адрес из шага 2):
   ```
   ssh mayak@IP
   ```
   На вопрос «Are you sure you want to continue connecting» напишите `yes` и Enter.
   Получилось, если строка стала начинаться с `mayak@mayachok:~$`.
2. Пока выйдите обратно: `exit`.

## Шаг 4. Сохранить данные с домашнего компьютера

Бот дома **должен быть запущен** (`docker compose up -d`).

1. Скачайте новый архив **mayachok-dlya-github.zip** (в нём есть скрипты для переезда) и распакуйте в папку проекта с заменой.
   Внутри архива папка `mayachok` — копируйте её **содержимое** в папку проекта.
2. Пересоберите бота дома, чтобы в нём появился инструмент переноса:
   ```
   docker compose up -d --build
   ```
3. В PowerShell в папке проекта:
   ```
   powershell -ExecutionPolicy Bypass -File scripts\export_data.ps1
   ```
   Появится папка **perenos**: копия базы, данные Redis (классы учителей, маяк, альбомы, карточки) и настройки `.env`.
4. **Сразу остановите бота дома** — два одинаковых бота одновременно мешают друг другу:
   ```
   docker compose stop bot
   ```

> В папке perenos — данные детей и токены. Никому её не отправляйте, только на свой сервер. После переезда её можно удалить.

## Шаг 5. Скопировать всё на сервер

В PowerShell, в папке, где лежат архив **mayachok-dlya-github.zip** и папка **perenos**:
```
scp mayachok-dlya-github.zip mayak@IP:~/
scp -r perenos mayak@IP:~/
```

## Шаг 6. Запустить бота на сервере

1. Зайдите на сервер: `ssh mayak@IP`
2. Распакуйте проект и подготовьте сервер (Docker, зеркало, подкачка, фаервол):
   ```
   sudo apt-get update && sudo apt-get install -y unzip
   unzip -q mayachok-dlya-github.zip
   bash mayachok/scripts/server_setup.sh
   exit
   ```
3. Зайдите снова (`ssh mayak@IP`) и запустите бота с вашими данными:
   ```
   cd mayachok
   bash scripts/server_import.sh ~/perenos
   ```
   Сборка займёт 3–7 минут. В конце: «Готово! Бот работает на сервере».
4. Проверьте: напишите боту в MAX `/start` — он должен ответить, и ваши ученики, классы и награды на месте.
   Посмотреть, что делает бот: `docker compose logs -f bot` (выход — Ctrl+C).

Теперь компьютер можно выключать. Сервер перезапускает бота сам — после сбоя и после перезагрузки сервера.

## Шаг 7. Мини-приложение по HTTPS (ссылка для организаторов)

MAX открывает мини-приложение только по **https**. Домен покупать не нужно: адрес будет вида
`https://51-250-12-34.sslip.io/` (бесплатный сервис sslip.io: имя = IP сервера), сертификат Let's Encrypt
сервер получит и будет продлевать сам.

1. В консоли Yandex Cloud проверьте, что у сервера открыты порты **80 и 443**: ВМ → «Сеть» → группа безопасности.
   Если группы безопасности нет — всё уже открыто, ничего делать не нужно.
2. На сервере, в папке `mayachok`:
   ```
   bash scripts/server_https.sh
   ```
   Через минуту появится: «Готово! Мини-приложение: https://…sslip.io/».
3. Откройте эту ссылку на телефоне в браузере — должно открыться приложение в демо-режиме (настоящие данные — только внутри MAX).
4. Отправьте организаторам **ссылку на бота** и **эту ссылку** — они привяжут приложение к боту.
5. Когда привяжут, включите кнопку приложения в меню бота: в `.env` поставьте `MINIAPP_BUTTON=true`
   (как менять `.env` — ниже) и выполните `docker compose up -d`.

Если позже появится свой домен — `bash scripts/server_https.sh ваш.домен.ru`
(в настройках домена A-запись должна указывать на IP сервера), а новую ссылку снова отправить организаторам.

## Как обновлять бота

Код бота лежит на GitHub: https://github.com/zsehevgen9-source/rep-bot-project

**Один раз** свяжите папку на сервере с GitHub (на сервере, команду целиком одной строкой):
```
cd ~/mayachok && git init -q && git remote add origin https://github.com/zsehevgen9-source/rep-bot-project.git && git fetch -q origin main && git reset -q --hard origin/main && git branch -M main && git branch -u origin/main
```
Файлы `.env`, база и данные учеников при этом не меняются.

**Каждое обновление** — одна команда на сервере:
```
bash ~/mayachok/scripts/server_update.sh
```
Скрипт возьмёт новую версию с GitHub, пересоберёт и перезапустит бота (2–3 минуты).

## Как поменять настройку в .env

```
ssh mayak@IP
cd mayachok
nano .env
```
Стрелками к нужной строке, исправьте, затем **Ctrl+O**, **Enter** (сохранить), **Ctrl+X** (выйти). Применить:
```
docker compose up -d
```

## Полезные команды (на сервере, в папке mayachok)

| Что сделать | Команда |
|---|---|
| Логи бота | `docker compose logs -f bot` |
| Логи HTTPS (мини-приложение) | `docker compose logs -f caddy` |
| Перезапустить бота | `docker compose restart bot` |
| Что запущено | `docker compose ps` |
| Остановить всё | `docker compose down` |
| Забрать копии базы домой (в PowerShell на компьютере) | `scp -r mayak@IP:~/mayachok/backups .` |

Копия базы делается сама раз в сутки в папку `backups` на сервере (хранятся 14 последних).

## Если что-то пошло не так

- **`ssh: connect … timed out`** — проверьте IP и что ВМ в статусе Running.
- **`Permission denied (publickey)`** — при создании ВМ вставлен не тот ключ или логин не `mayak`. Ключ можно поменять в консоли ВМ → «Изменить».
- **Бот не отвечает** — `docker compose logs --tail 50 bot`, смотрите последние строки с ошибкой.
- **Бот отвечает дважды или «конфликт»** — дома бот не остановлен: на компьютере `docker compose stop bot`.
- **Не скачиваются образы Docker** — `server_setup.sh` уже настроил зеркало; если всё равно ошибка, повторите `bash scripts/server_import.sh ~/perenos` через несколько минут.
